## 1. What changed

### 1.1 `render.js` `NEWS_SPORT` (was line 386) — headline eligibility

```diff
-  const NEWS_SPORT = new Set(["world", "local", "finance", "football", "golf"]);
+  const NEWS_SPORT = new Set([
+    "world", "local", "finance",
+    "football", "golf", "sport", "cricket", "cycling", "athletics",
+  ]);
```

| addition | one-line reason |
|----------|-----------------|
| `cricket` | A Test or Ashes result is a big Sport story by the same standard as a golf major; without this it could only lead Headlines by accident (corroboration or a confirmed/official verb). |
| `cycling` | A grand-tour stage win or GC swing is a result of record, not a browse item. |
| `athletics` | A world record or a championship final is the single biggest thing that happens in the sport. |
| `sport` | The catch-all carries the multi-sport meets (Commonwealths, Olympics) and every sport with no domain of its own — the exact class of story defect D says vanished. |
| `motorsport` — **NOT added** | `interest_depth: "results_only"` and the owner's stated position (*"F1 is at best a passing interest, nice to know big results, I don't need a minute by minute"*). Excluding it from the free pass leaves a race win reachable via corroboration (≥2 feeds) or a confirmed/official title, while a practice/qualifying item is not. Demonstrated both ways in §3.1. |

**Failure mode I checked for before touching this.** The comment above the set records that it was
already broadened once because a football/gaming-heavy day collapsed Headlines to ~2. `NEWS_SPORT` is
one disjunct of a five-way **OR** (`headlineEligible`), i.e. a *broadening* clause — adding domains can
only ever make more items eligible, so the collapse-to-2 failure cannot be reintroduced by this change.
The opposite risk is real and is recorded as a handoff in §5: Headlines has no guaranteed news slot, so
a very heavy sport day now has more eligible sport domains competing for the 8 slots. It is bounded by
the existing ≤2/domain cap and by importance ranking (the new domains' weights are 0.4–0.45 against
football's 0.85, so their confidences are structurally lower), but it is not bounded to zero.

### 1.2 `render.js` `DOMAIN_LABELS` (lines 8–25) — display fallback

Added `sport: "More Sport"`, `cricket: "Cricket"`, `cycling: "Cycling"`, `athletics: "Athletics"`,
`motorsport: "Motorsport"`. Values copied from `profile.js` `DOMAIN_META` (lines 420–424), not guessed;
verified equal in §3.2.

**Honest scope of this fix.** `labelFor` is `topic_weights[d].label || DOMAIN_LABELS[d] || titleCase(d)`,
so the fallback only runs for a config with no `topic_weights`. Of the five, only **`sport` was actually
broken** there — it fell through to `titleCase("sport")` = `"Sport"`, which contradicts the profile's
`"More Sport"`. The other four are single words that `titleCase` already produced correctly. They are
added anyway so the fallback table stays a true mirror of the profile rather than being right by
coincidence, which is what WP-7 asked for. Measured before/after in §3.2.

### 1.3 `dedup.js` `RELAXED_DOMAINS` (was line 54) — near-duplicate merging

```diff
-const RELAXED_DOMAINS = new Set(["football"]);
+const RELAXED_DOMAINS = new Set(["football", "cricket"]);
```

**`cricket`** — one line: the BBC files several variants of the same match report, which land in the
0.35–0.50 Jaccard band that the strict same-domain rule misses.

I did **not** take this on faith. `RELAXED_DOMAINS` is read at `dedup.js:127` (now 135) as
`j >= 0.5 || (relaxed && j >= ENTITY_JACCARD && sharesEntity(...))`, so the only thing it can do is
merge pairs scoring **between 0.35 and 0.50 that share a proper noun**. I measured how that band is
populated per sport against the live BBC feeds (§3.3). Cricket has the shape; three other sports were
measured the same way and **rejected** (§3.4).

## 2. Full audit of hardcoded domain lists in these two files

`grep -n 'new Set(' functions/daily/render.js functions/daily/dedup.js` plus a sweep for string
equality against domain names (`=== "`, `[ "`) found **seven** hardcoded string lists across the two
files. Three are domain lists needing the new sports; two are domain lists that must *not* have them;
two are not domain lists at all.

| # | Location | What it is | Call |
|---|----------|------------|------|
| 1 | `render.js:8–25` `DOMAIN_LABELS` | domain → display label (fallback) | **CHANGED** — §1.2 |
| 2 | `render.js:386` `NEWS_SPORT` | headline eligibility | **CHANGED** — §1.1 |
| 3 | `dedup.js:54` `RELAXED_DOMAINS` | relaxed near-duplicate merge | **CHANGED** (`cricket` only) — §1.3 |
| 4 | `render.js:103` `d === "football" \|\| d === "film_tv" \|\| d === "gaming"` | Today & Tonight domain gate — **fallback only** | **NOT changed** |
| 5 | `render.js:203` `NEWS = new Set(["world","finance"])` | Top Catches guaranteed news slot + eviction protection | **NOT changed** |
| 6 | `render.js:275` `edition === "news_money"` | edition literal, not a domain | **NOT changed** |
| 7 | `render.js:371` `COMMUNITY_SRC = {reddit, hn, bluesky}` | `source_type` literal, not a domain | **NOT changed** |

Not domain lists, listed for completeness: `dedup.js:8` `STOP` and `render.js:125` `SIG_STOP` are token
stoplists (`SIG_STOP` carries football-transfer vocabulary — `deal`, `move`, `bid`, `eye`, `set` — but
it is generic title-noise removal, not routing); `render.js:82` `["discussion","article","post","feed"]`
is a link-type preference order.

**Why #4 is left alone.** It is only reached when `flagged.size === 0`, i.e. when *no* topic in the
config sets `today_tonight`. Profile v8 sets it on seven domains (§3.5), so this branch is unreachable
with any current config, and its comment states its purpose is that "an un-migrated config behaves
exactly as before". Adding sports here would change legacy-config behaviour and gain nothing. The live
path (`topic_weights[d].today_tonight`) already routes the new domains, including WP-7's deliberate
omission of motorsport — verified in §3.5.

**Why #5 is left alone.** `NEWS` is not a sport list. It names the domains whose Top Catches slot is
*guaranteed* (`guarantee((i) => NEWS.has(i.domain), …)`) and simultaneously the domains protected from
eviction (`(s) => !s.entity_floor && !NEWS.has(s.domain)`). Adding cricket/cycling/athletics/sport would
let a sport item **satisfy** the news guarantee and would make world/finance **evictable** — the exact
opposite of the intent, and a regression on a sport-heavy day. §3.6 shows the current behaviour.

**Nothing is dropped on the floor by #6 or #7.** The new domains carry `edition: "sport"`, so at #6 they
take the confidence-ordered browsing branch (correct — they are not News & Money), and #7 keys on
`source_type`, which is `rss`/`reddit` regardless of domain.

### 3.3 Cricket near-duplicate collapse — before/after

Case A uses the **real** pair from the live BBC cricket feed on 2026-07-26; B, C and D are controls.

```
$ node h-dedup-ba.mjs

   before: 2 items -> 2 cluster(s)
   after : 2 items -> 1 cluster(s)
      [2 member(s)] Phoenix beat Rockets in high-scoring thriller

B) two DIFFERENT cricket matches sharing an entity — MUST stay separate
   before: 2 items -> 2 cluster(s)
   after : 2 items -> 2 cluster(s)
      [1 member(s)] England beat India by five wickets at Lord's
      [1 member(s)] England thrash India by an innings at Headingley

   before: 2 items -> 2 cluster(s)
   after : 2 items -> 2 cluster(s)
      [1 member(s)] England beat India by five wickets at Lord's
      [1 member(s)] England name unchanged squad for India Test series

D) FOOTBALL regression control — behaviour must be identical before/after
   before: 2 items -> 2 cluster(s)
   after : 2 items -> 2 cluster(s)
```

Whole-feed regression, every live BBC sport feed through both versions:

```
$ node h-regress.mjs
football     77 items  before= 72 after= 72  IDENTICAL
golf         30 items  before= 27 after= 27  IDENTICAL
cricket      48 items  before= 44 after= 42  CHANGED
   newly collapsed:
     - Phoenix beat Rockets in high-scoring thriller
     - Birmingham Phoenix beat Trent Rockets in record-breaking thriller
   newly collapsed:
     - The Hundred 2026 squads
     - The Hundred 2026 - schedule and how to follow
     - What has changed in The Hundred for 2026?
cycling      19 items  before= 19 after= 19  IDENTICAL
athletics    40 items  before= 40 after= 40  IDENTICAL
motorsport   19 items  before= 19 after= 19  IDENTICAL
sport        81 items  before= 77 after= 77  IDENTICAL
```

Only cricket changed; 2 merges in 48 items; **football and golf byte-identical**, so §"do not change
existing football/golf behaviour" holds.

**The cost, stated plainly.** The second cricket merge is not a match report — it is three *The Hundred
2026* reference pages (squads / schedule / what changed) collapsing into one card. They are the same
tournament furniture rather than three distinct events, and `mergeLinks` caps a cluster at one article
link, so two of those three URLs stop being reachable from the card. I judged this acceptable: it is
evergreen boilerplate, one line in a brief either way, and it is the identical trade-off football has
run with since the relaxed clause was written. It is the reason I did not extend the relaxation any
further than cricket.

### 3.4 Why `cycling`, `athletics` and `golf` were NOT added

Same measurement, run per sport by relabelling a feed's live items to `football` (the only relaxed
domain) and diffing the clusters against the strict run. The extra collapses are exactly what adding
that domain to `RELAXED_DOMAINS` would do.

```
$ node h-relaxed-pairs.mjs

=== cricket (48 items): strict 44 -> relaxed 42 clusters ===
  MERGED GROUP:
     - Phoenix beat Rockets in high-scoring thriller
     - Birmingham Phoenix beat Trent Rockets in record-breaking thriller   <-- TRUE duplicate
  MERGED GROUP:
     - The Hundred 2026 squads
     - The Hundred 2026 - schedule and how to follow
     - What has changed in The Hundred for 2026?                          <-- boilerplate, tolerable

=== cycling (19 items): strict 19 -> relaxed 18 clusters ===
  MERGED GROUP:
     - Pogacar set to equal Tour record as Carapaz wins stage
     - Carapaz wins stage as Pogacar's team suffers sickness               <-- two ANGLES, one lost

=== athletics (40 items): strict 40 -> relaxed 38 clusters ===
  MERGED GROUP:
     - Johnson-Thompson and Asher-Smith out of Commonwealths
     - Johnson-Thompson in England team for Commonwealths                  <-- CONTRADICTORY, bad merge
  MERGED GROUP:
     - 'Unbelievable!' - GB's Kerr breaks mile world record
     - 'Following in the footsteps of legends' - Kerr smashes mile world record in London

=== golf (30 items): strict 27 -> relaxed 26 clusters ===
  MERGED GROUP:
     - 'Can you believe it?' - Best shots from final round of The Open
     - 'Absolutely fabulous' - best shots from third round of The Open      <-- DIFFERENT ROUNDS
```

- **`athletics` rejected.** The relaxation merges *"Johnson-Thompson in England team"* with
  *"Johnson-Thompson out of Commonwealths"* — two stories that contradict each other. Collapsing them
  hides the later, more important one. One true positive is not worth that.
- **`cycling` rejected.** The single merge is two different angles on the same stage, not a variant of
  one report; one angle is silently lost, and only 1 candidate appeared in 19 items. WP-7 said
  "consider" cycling; the measurement says no.
- **`golf` rejected**, and this is the useful control: the relaxation merges The Open's third-round and
  final-round round-ups. That is why golf was never in this set, and confirms the instruction not to
  change golf behaviour is correct rather than merely conservative.

Also worth recording: relaxed matching does **not** catch the most-drifted variant. WP-7's third live
title, *"Seven sixes - Ravindra smashes 98 from 44 balls"*, shares only `{ravindra, 98}` with its
sibling report (j ≈ 0.18) and stays a separate cluster. Cricket duplicate collapse is improved, not
solved.

## 5. Handoff notes

1. **Headlines has no guaranteed news slot, and now has four more eligible sport domains.** Top Catches
   protects world/finance via `NEWS` + `guarantee()`; Headlines has no equivalent. The ≤2/domain cap
   and importance ranking bound the risk (the new domains sit at 0.4–0.45 against football's 0.85), and
   `headline_max` is 8, so a day with big results across football, golf, cricket, cycling, athletics and
   the catch-all could in principle fill the set with sport. This is a *policy* question (should
   Headlines guarantee a news slot?), not a routing bug, and it is outside WP-11's two files — flagging
   for the owner rather than inventing a guarantee.
2. **`SIG_STOP` (`render.js:125`) is football-shaped.** It strips `deal`, `move`, `bid`, `eye`, `set` as
   title noise — tuned for transfer rumours. Harmless for the new sports, but if cricket/cycling
   headlines ever over- or under-collapse in Top Catches, this stoplist is the place to look.
3. **`DOMAIN_LABELS` is now a true mirror of `profile.js` `DOMAIN_META`.** Anyone adding a domain to the
   profile should add it here too, or accept `titleCase` (which was wrong for exactly one of the five
   labels, `sport` → `"Sport"` instead of `"More Sport"`).
4. **For WP-4/WP-3 (`data-sport`, §3.11):** the daily's routing namespace after this WP is
   `football | golf | sport | cricket | cycling | athletics | motorsport`. `sport` is a *routing*
   catch-all, not a sport token, so it must not be emitted as `data-sport`; multi-sport games items
   collect there and need splitting into specific sport tokens, which is consistent with the SPEC's
   ban on `data-sport="multi_sport"`.
5. **Acceptance criterion #11** ("the daily surfaces a cricket/cycling/athletics item — feed parses,
   domain routes") is credited to WP-7 for ingest/scoring; the routing half — those items being
   headline-eligible, labelled, deduped and admitted to Today & Tonight — is evidenced in §3.1, §3.2,
   §3.3 and §3.5 here.
