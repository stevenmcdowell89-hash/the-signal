Push setup

Generates the three Cloudflare env vars + the KV binding name you need to turn on push notifications. Runs entirely in this browser — keys are never sent anywhere.

One-time only. Regenerating overwrites the existing keys; every device already subscribed will need to be re-subscribed (re-open the PWA, accept the prompt again).

1. Env vars

Cloudflare Pages → your project → Settings → Functions → Production env vars → Add variable. Set the first as plaintext, the other two as secrets.

VAPID_PUBLIC_KEY Plaintext
Press Generate to populate
VAPID_PRIVATE_KEY Secret
Press Generate to populate
NOTIFY_AUTH_TOKEN Secret
Press Generate to populate
VAPID_SUBJECT Plaintext · optional
mailto:steven.mcdowell.89@gmail.com

2. KV binding

Same page in the dashboard → KV namespace bindings → Add binding:

  1. Variable name: SUBSCRIPTIONS
  2. KV namespace: create one (call it signal-push-subs), then select it.

3. Redeploy

Deployments tab → latest deploy → Manage deployment → Retry deployment. Env vars and KV bindings only take effect on a new deploy.

4. Sunday trigger

Claude Code on the Web — the trigger that runs the Sunday pipeline. Add two env vars there too so the pipeline can call /api/notify after publishing:

  1. NOTIFY_AUTH_TOKEN — same value as above.
  2. SIGNAL_NOTIFY_HOST — your Pages host (e.g. the-signal.pages.dev, or a custom domain).

5. Subscribe this device

Open the PWA (Add to Home Screen if you haven't), tap the Signal icon, accept the notification prompt. That's it — every issue from then on triggers a push.
